# PCO v0.5 Canonical Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the v0.5 append-only canonical data model and the mem-core application commit boundary that proposal commits will use.

**Architecture:** Keep mem-core Profile-neutral and preserve its Git-worktree transaction engine. Add a Profile-declared application commit policy, an OS-backed canonical lock, and a one-shot application transaction API whose caller supplies normalized operations, deterministic transaction digest, and proposal receipt; PCO supplies the v0.5 Profile and semantic validators.

**Tech Stack:** Python 3.11+, Pydantic 2, JSON Schema Draft 2020-12, PyYAML, Git CLI, pytest.

**Spec:** `docs/superpowers/specs/2026-08-30-pco-v0.5-agent-agnostic-design.md`

## Global Constraints

- PCO v0.5 is a clean break: do not accept or migrate v0.3/v0.4 streams or schema versions.
- Canonical business streams are exactly `evidence`, `sources`, `events`, `psychologies`, `philosophies`, `archetypes`, `hypotheses`, `meta_revisions`, and `session_handoffs`.
- Canonical changes append complete revisions; retirement appends a tombstone and never deletes history.
- `transactions` is the internal audit ledger; a proposal receipt lives in its transaction line.
- The v0.5 Profile declares `application_commit_policy: pco_proposal`; public `mem` writes to its business streams fail with `DIRECT_PCO_STREAM_WRITE_FORBIDDEN`.
- The application commit capability is a structural misuse guard, not a security boundary against arbitrary Python execution.
- Only the canonical transaction and Git commit require locking, atomicity, and idempotent retry.
- `recorded_at`, `committed_at`, and the Git commit are excluded from `transaction_digest`.
- `ApplicationCommitRequest` carries no caller-selected transaction ID; mem-core derives `txn_<digest-hex>` from `transaction_digest` and uses it for the ledger and deterministic application-worktree cleanup.
- Constructing `TransactionManager` is read-only; generic transaction state and one-shot application worktrees are created only by their respective mutating methods.
- Python package, workspace format, Profile, proposal manifest, and SKILL compatibility for v0.5 are `>=0.5.0,<0.6.0`.

```python
@contextmanager
def canonical_lock(path: Path, *, blocking: bool = True) -> Iterator[None]:
    path.parent.mkdir(parents=True, exist_ok=True)
    descriptor = os.open(path, os.O_RDWR | os.O_CREAT, 0o600)
    acquired = False
    try:
        _lock_descriptor(descriptor, blocking=blocking)
        acquired = True
        yield
    except BlockingIOError as exc:
        raise MemError(
            "CANONICAL_LOCKED", "canonical_lock", "Canonical transaction is already running",
            canonical_changed=False, retry_safe=True,
            recovery=["Retry pco proposal commit after the active command finishes"],
        ) from exc
    finally:
        if acquired:
            _unlock_descriptor(descriptor)
        os.close(descriptor)
```

Use `fcntl.flock` on POSIX and `msvcrt.locking` on Windows. Store the lock at `<git-common-dir>/pco-canonical.lock`, so process death releases ownership without a cleanup state machine.

```python
class ApplicationCommitRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    policy: str
    transaction_digest: str = Field(pattern=r"^sha256:[0-9a-f]{64}$")
    base_commit: str
    operations: list[Operation] = Field(min_length=1)
    receipt: dict[str, Any]


def application_transaction_id(transaction_digest: str) -> str:
    ensure(
        re.fullmatch(r"sha256:[0-9a-f]{64}", transaction_digest) is not None,
        "TRANSACTION_HASH_MISMATCH", "application_commit", "Invalid application transaction digest",
    )
    return "txn_" + transaction_digest.removeprefix("sha256:")
```

The model and helper are importable by PCO but are not exposed by the `mem` argument parser. The caller supplies no transaction ID; mem-core derives it from the validated digest for ledger identity, commit messages, and owned worktree paths.

```python
def __init__(self, repository: MemoryRepository, state_root: Path) -> None:
    self.repository = repository
    self.state_root = state_root.resolve()
    self.transactions_root = self.state_root / "transactions"


def _save(self, state: TransactionState) -> None:
    state.updated_at = utc_now()
    target = self._state_path(state.id)
    target.parent.mkdir(parents=True, exist_ok=True)
    temporary = target.with_suffix(".tmp")
    temporary.write_text(state.model_dump_json(indent=2), encoding="utf-8")
    os.replace(temporary, target)


def begin(self, *, fingerprint_context: dict[str, Any], transaction_id: str | None = None) -> TransactionState:
    ensure(
        self.repository.profile.config.application_commit_policy == "public",
        "DIRECT_PCO_STREAM_WRITE_FORBIDDEN", "write_policy",
        "PCO business streams can only be written through pco proposal commit",
    )
    return self._begin_public(fingerprint_context=fingerprint_context, transaction_id=transaction_id)


def commit_application(self, request: ApplicationCommitRequest, *, lock_held: bool = False) -> dict[str, Any]:
    ensure(request.policy == self.repository.profile.config.application_commit_policy,
           "DIRECT_PCO_STREAM_WRITE_FORBIDDEN", "write_policy", "Application commit policy mismatch")
    context = nullcontext() if lock_held else self.repository.lock()
    with context:
        duplicate = self._find_committed_fingerprint(request.transaction_digest)
        if duplicate is not None:
            ensure_duplicate_matches_request(duplicate, request)
            self._cleanup_application_attempt(
                request.transaction_digest, review_id=str(request.receipt["review_id"])
            )
            return {"ok": True, "idempotent": True, "commit": duplicate["commit"], "transaction": duplicate}
        ensure(self.repository.head() == request.base_commit, "CANONICAL_HEAD_CHANGED", "transaction_validation",
               "Canonical HEAD changed before commit", canonical_changed=False, retry_safe=False,
               recovery=["Create a new proposal from pco proposal scaffold against the current HEAD"])
        return self._commit_application_worktree(request)
```

`TransactionManager.__init__` only stores normalized paths. Generic persistent transaction directories are created by `_save()` when `begin` or another generic mutating method actually persists state. The one-shot application path never calls `_save()`.

The duplicate lookup is intentionally before the stale-HEAD check: a successful first commit necessarily advances HEAD beyond `request.base_commit`. Duplicate verification compares only the fields bound by `transaction_digest`:

```python
def application_identity_view(value: ApplicationCommitRequest | Mapping[str, Any]) -> dict[str, Any]:
    if isinstance(value, ApplicationCommitRequest):
        data = value.model_dump(mode="json")
        data["transaction_id"] = application_transaction_id(value.transaction_digest)
    else:
        data = {
            "policy": value["application_policy"],
            "transaction_id": value["id"],
            "transaction_digest": value["transaction_fingerprint"],
            "base_commit": value["base_commit"],
            "operations": value["operations"],
            "receipt": value["receipt"],
        }
    receipt = deepcopy(data["receipt"])
    receipt.pop("committed_at", None)
    operations = []
    for raw in data["operations"]:
        operation = raw if isinstance(raw, Operation) else Operation.model_validate(raw)
        normalized = operation.model_dump(mode="json", exclude_none=True)
        if normalized.get("op") == "append" and isinstance(normalized.get("record"), dict):
            normalized["record"].pop("recorded_at", None)
        operations.append(normalized)
    return {
        "policy": data["policy"],
        "transaction_id": data["transaction_id"],
        "transaction_digest": data["transaction_digest"],
        "base_commit": data["base_commit"],
        "operations": operations,
        "receipt": receipt,
    }
```

Normalize every request-side and ledger-side operation through the same `Operation.model_validate(...).model_dump(mode="json", exclude_none=True)` path before comparison; never compare Pydantic's default serialization with ledger-normalized bytes. Do not recursively remove arbitrary fields: only receipt `committed_at` and append-record `recorded_at` are nondeterministic and excluded from the digest contract. The stored ledger ID is compared with the request's mem-core-derived ID, so a copied or forged ID fails with `WORKSPACE_INTEGRITY_ERROR`.

Application attempts use a separate deterministic subtree:

```python
def _application_attempt_dir(self, transaction_digest: str) -> Path:
    return self.state_root / "application-worktrees" / application_transaction_id(transaction_digest)


def _application_worktree_path(self, transaction_digest: str) -> Path:
    return self._application_attempt_dir(transaction_digest) / "worktree"


def rmdir_if_empty(path: Path) -> None:
    try:
        path.rmdir()
    except FileNotFoundError:
        return
    except OSError as exc:
        if exc.errno != errno.ENOTEMPTY:
            raise


def _cleanup_application_attempt(self, transaction_digest: str, *, review_id: str) -> None:
    attempt = self._application_attempt_dir(transaction_digest)
    worktree = attempt / "worktree"
    self.repository.remove_worktree(worktree)
    ensure(not worktree.exists(), "CANONICAL_WORKTREE_CLEANUP_FAILED", "application_cleanup",
           "Committed application worktree could not be removed", canonical_changed=True, retry_safe=True,
           recovery=[f"pco proposal commit {review_id}"])
    rmdir_if_empty(attempt)
    rmdir_if_empty(attempt.parent)
```

`_commit_application_worktree` derives the ID internally, removes any stale worktree for that same digest before preparing it, validates operations, appends them and one transaction ledger line containing derived `id`, `application_policy`, `base_commit`, normalized `operations`, `transaction_fingerprint`, and `receipt`, then stages the complete worktree, commits, fast-forwards, and calls `_cleanup_application_attempt(request.transaction_digest, review_id=request.receipt["review_id"])` before returning. Store `transaction_fingerprint` equal to `request.transaction_digest`, never recompute it from timestamps, and never call `begin`, `_save`, `load`, or any other persisted `TransactionState` API. A process death may interrupt before cleanup; deterministic duplicate retry is the recovery path. `rmdir_if_empty` removes only these known owned empty parents and never recursively deletes unexpected entries.

        raw_application_snapshot,
