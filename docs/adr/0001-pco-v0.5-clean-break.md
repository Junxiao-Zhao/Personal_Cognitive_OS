# ADR 0001: PCO v0.5 clean break

- Status: Accepted
- Date: 2026-08-30
- Product version: 0.5.0

## Context

PCO v0.3 and v0.4 coupled the product runtime to a particular Agent Harness,
durable checkpoints, conversation archives, compact orchestration, and
provider-specific projections. Those surfaces obscured the durable boundary:
the canonical append-only memory in Git. PCO v0.5 instead targets any Agent
Host that supports project-local skills, shell commands, and one-time write
permission escalation.

## Decision

PCO v0.5 is an accepted clean break with no v0.3/v0.4 workspace migration or
schema-compatibility path. Superseded runtime, resources, tests, and active
product documents are removed; Git history remains their historical record.

Each PCO instance is a dedicated workspace. `pco init [PATH]` accepts only a
nonexistent or empty target and installs the canonical repository, disposable
derivations, proposal area, and project-local `.agents/skills` there. PCO does
not embed itself into an existing project and does not install global or
Host-specific runtime adapters.

The only strongly atomic transaction boundary is a mem-core canonical
transaction and its Git commit. Human-readable proposals are validated before
commit and archived afterward. Proposal archives, `PCO_MEMORY`, retrieval
indexes, and installed workspace-local skills are non-canonical artifacts;
derivation or archival failure never rolls back a successful canonical commit.
Disposable derivations carry source commit and hash manifests so missing,
stale, or mixed outputs are detected and rebuilt from canonical data.

The public Agent workflow is proposal based: author files under
`PCO_PROPOSALS/<review_id>/`, validate them, and invoke only
`pco proposal commit <review_id>` for the canonical write. Host permission
policy supplies the proposal Edit and commit-command boundaries. PCO does not
capture Host authorization tokens or claim machine proof of a TUI approval.

## Consequences

- Harness adapters, checkpoints, compact commands, conversation archives,
  AFFiNE and legacy Markdown projection capabilities, source-add, and public
  backlinks/context surfaces do not exist in v0.5.
- Reads and validation are side-effect free. Search uses a verified disposable
  index or a bounded canonical fallback.
- Recovery starts from canonical Git data. No migration engine, derivation
  journal, background daemon, or Host-specific installer is retained.
- Users restore or copy a complete canonical repository to preserve workspace
  identity; old v0.3/v0.4 workspaces are not opened in place.
